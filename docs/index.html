Three teams, three answers. Now there is one.

Ask “what was on-time delivery for Pune in September?” and every team’s report says something different, because each one measures a different event against a different date. We built one governed definition that every person and every tool shares.

How it works

Metric logic lives in exactly one place: a Snowflake semantic view. Everything else reads from it. Cortex Code planned, built and tested every layer, following a rule file (AGENTS.md) that it checks before each change.

  1. Sources

    ERP, supplier portal, logistics and IoT data, plus 10 signed supplier contract PDFs.

  2. Conformed

    17 dynamic tables holding events and cost components. No metric is calculated here.

  3. Semantic view

    SV_SUPPLY_CHAIN: five canonical metrics, named variants, synonyms and 22 verified queries.

  4. Agent

    One Cortex Agent with contract search and two actions that ask for confirmation and are audited.

  5. Surfaces

    Snowflake Intelligence, a Streamlit app and the Cortex Code CLI, all giving the same number.

It refuses what isn’t defined. Ask for “truck fill rate” and it explains that the metric doesn’t exist and offers the real one.

It asks before acting. Expediting a PO or flagging a supplier waits for a yes, and every action is written to an audit log.

It surfaces bad data. 4,900 purchase order lines carry an Incoterm that contradicts the signed contract. Both sides are kept and reported.
